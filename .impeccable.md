## Design Context

### Users

API and report developers using the tool as a daily local workspace. Their core jobs
are browsing Postman collections, testing individual requests, writing report scripts,
and inspecting or exporting generated Excel workbooks without switching applications.

### Brand Personality

Calm, precise, and utilitarian. The product should feel dependable during focused,
technical work and make dense information easy to scan.

### Aesthetic Direction

A refined developer workbench influenced by Postman's request workflow and SQL
Developer's information density. Use the existing light, muted green editorial palette
with a dark application chrome. Avoid generic SaaS cards, decorative gradients, neon
developer styling, oversized typography, and excessive rounded containers.

### Design Principles

1. Keep the active request, action, and response visually dominant.
2. Reveal advanced detail progressively while keeping common actions immediate.
3. Use dense but readable tables that behave like practical data tools.
4. Preserve context when switching between collections, scripts, and workbooks.
5. Make loading, success, failure, and empty states unambiguous and accessible.
