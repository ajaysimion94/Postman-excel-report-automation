Build filters and Excel reports.

01

Quick start

This example runs now with the bundled Reqres collection.

COLLECTION reqres;
REQUESTS "List users page 1", "Get single user";
OUTPUT_PREFIX reqres-report;

FILTER "List users page 1" WHERE id > 0;
COLUMNS "List users page 1":
  id AS "User ID",
  first_name AS "First name",
  last_name AS "Last name",
  email AS "Email";
SHAPE "List users page 1" ORDER BY id ASC LIMIT 20;

$USERS = FILTER "List users page 1" WHERE id > 0;

SUMMARY {
  TITLE "Reqres user report" COLOR "#315D72";
  DESCRIPTION "Users returned by the public API.";
  METRIC "Users" = $USERS;
  PARAGRAPH IF $USERS = 1 THEN "One user was returned."
    ELSE $USERS + " users were returned.";
  TABLE $USERS TITLE "Users"
    COLUMNS id AS "ID", first_name AS "First name", email AS "Email";
  STATUS;
  METRICS;
}

Run it: save as a .filter file, select the matching collection, choose Validate, then choose Run report. Every statement ends with ;; the semicolon after a SUMMARY block is optional.

02

Select what runs

Choose the collection, requests, and output filename.

COLLECTION

Targets one Postman collection. The name must match its filename or collection name.

COLLECTION reqres;

REQUESTS / REQUEST

Select several requests or add one request. Without either statement, every request runs.

REQUESTS "List users", "Get user";
REQUEST "List users";
REQUEST "List users" WHERE active IS TRUE;

OUTPUT_PREFIX

Sets the generated workbook filename prefix. Both forms are equivalent.

OUTPUT_PREFIX daily-report;
SET OUTPUT_PREFIX daily-report;

Multiple collections

Statements before the first collection are global defaults. Select one block using the collection picker or CLI option.

SHAPE * LIMIT 200;

COLLECTION users;
REQUESTS "List users";

COLLECTION orders;
REQUESTS "List orders";
03

Filter response rows

Predicates support grouping, comparisons, strings, dates, runtime variables, and conditional branches.

FILTER "List users" WHERE id >= 2 AND id <= 5;
FILTER * WHERE (status = active OR priority = high) AND NOT archived IS TRUE;
FILTER "Orders" WHERE region IN ('US','CA') AND tier = $minTier;

Evaluation order

  1. Parentheses
  2. NOT
  3. AND

Numbers compare numerically first. Other values compare as case-insensitive text.

Conditional filtering

FILTER * WHERE
  IF priority = high
  THEN (severity > 7)
  ELSE (severity > 3);

Without ELSE, a false condition lets the row pass.

Runtime variables

Use $name as a predicate value. Values resolve from the environment, credential profile, and filter configuration. A missing variable logs a warning and usually matches no rows.

FILTER "Orders" WHERE ownerId = $targetUser;
FILTER "Orders" WHERE region = $region AND amount >= $minimum;
04

Select and rename columns

Project fields after filtering and shaping. Dot paths read flattened nested JSON.

COLUMNS "List users":
  id AS "User ID",
  profile.name AS "Name",
  company.address.city AS "City";

COLUMNS *: id, createdAt;

The exact request key replaces the * default. Request-level columns affect response sheets and summary variables sourced from that request; they do not alter lookup, union, set-operation, or compare source rows.

05

Parse and filter dates

Declare the format when automatic ISO-8601 parsing is not enough.

DATE_CONFIG *.createdAt
  FORMAT "yyyy-MM-dd'T'HH:mm:ss'Z'"
  TIMEZONE UTC;

FILTER "Events" WHERE createdAt DATE_PRESET THIS_MONTH;
FILTER "Events" WHERE createdAt BETWEEN 2026-01-01 AND 2026-01-31;

Presets: TODAY, YESTERDAY, THIS_WEEK, LAST_WEEK, THIS_MONTH, LAST_MONTH, THIS_QUARTER, LAST_QUARTER, THIS_YEAR, LAST_YEAR.

Without TIMEZONE, the system timezone is used. A row does not match when its date cannot be parsed. For request names containing spaces, prefer DATE_CONFIG *.field.

06

Shape output datasets

Sort, page, deduplicate, group, and aggregate after rows are collected.

SHAPE "List users" DISTINCT ORDER BY id DESC LIMIT 50 OFFSET 0;

SHAPE "Orders"
  GROUP BY region
  AGG COUNT(*) AS order_count,
      SUM(amount) AS total,
      AVG(amount) AS average,
      MIN(amount) AS minimum,
      MAX(amount) AS maximum
  HAVING order_count > 1
  ORDER BY total DESC;

Repeated SHAPE statements merge clause types; the later value replaces the same clause. COUNT(*) is valid, but SUM(*), AVG(*), MIN(*), and MAX(*) are not. An exact output name replaces SHAPE *.

07

Expand nested arrays

Create one output row per array item while repeating its parent fields.

EXPAND "Catalog" ON items;
EXPAND "Catalog" ON items AS extras;

# Input
[{"category":"fruit","items":[{"id":1,"name":"apple"}]}]

# Output fields
category, items.id, items.name

EXPAND runs before FILTER and SHAPE. It requires an exact request name; * is not supported. Sparse child fields are grouped under the exception label.

08

Combine and compare API data

Build detail tables, merged datasets, differences, intersections, and value matrices.

LOOKUP_TABLE

Calls a detail request once for each source row. BY id AS itemid injects the source ID as {{itemid}}. Detail fields use the detail. prefix.

LOOKUP_TABLE "Items With Details"
  FROM "List Items"
  LOOKUP "Get Item Details"
  BY id AS itemid
  WHERE detail.price >= 1000
  COLUMNS id, name, detail.price;

UNION

Merges two or more raw request datasets. The default removes duplicate rows; ALL preserves them.

UNION "All Items"
  FROM "Active Items", "Archived Items" ALL;
SHAPE "All Items" ORDER BY id ASC;

INTERSECT

Keeps complete rows found in every source and adds _source and _in_… provenance fields.

INTERSECT CommonRows
  FROM "System A", "System B";

EXCEPT

Keeps complete rows from the first source that do not occur in any later source.

EXCEPT MissingFromB
  FROM "System A", "System B";

DIFF

Returns the symmetric difference, grouped by source with provenance columns.

DIFF Mismatches
  FROM "System A", "System B";

COMPARE

Compares one field across sources. The result contains the value, one presence column per source, and _count.

COMPARE IdMatrix ON id
  FROM "System A", "System B"
  WHERE id > 0
  HAVING _count > 1;

Set operations compare the complete JSON serialization of each row. They require at least two source requests. COMPARE compares only the named field. All sources are raw request rows; request-level FILTER and COLUMNS do not change these inputs.

09

Compose the Summary sheet

Capture datasets as variables, then present counts, prose, tables, and request health.

Summary variables

$TOP = FILTER $USERS WHERE id > 3;
$DETAILS = TABLE "Items With Details";
$ALL = UNION FROM "System A", "System B" ALL;
$COMMON = INTERSECT FROM "System A", "System B";
$ONLY_A = EXCEPT FROM "System A", "System B";
$CHANGES = DIFF FROM "System A", "System B";
$IDS = COMPARE ON id FROM "System A", "System B";

Colors

TITLE, DESCRIPTION, and STATUS accept COLOR "#RRGGBB" or a named color. Common names include DARK_BLUE, DARK_GREEN, SEA_GREEN, TEAL, GOLD, VIOLET, RED, ROSE, BROWN, INDIGO, and GREY_40_PERCENT. Any Apache POI IndexedColors name is accepted.

One-row, one-column variables display their cell value; multi-row variables display a row count. Boolean values (true/false and yes/no) receive success/failure formatting. Summary statements may also appear outside SUMMARY { … }.

10

Execution rules and workbook output

Know when each transformation runs and what it can target.

OutputExecution order
Response sheetRaw rows → EXPAND → FILTER → SHAPE → COLUMNS
Lookup tableRaw source → detail requests → lookup WHERE → SHAPE → lookup COLUMNS
UnionRaw rows → UNION → SHAPE
Set operationRaw rows → INTERSECT/EXCEPT/DIFF → SHAPE
CompareRaw rows → COMPARE value matrix → SHAPE

Valid wildcard targets: COLUMNS *, FILTER *, DATE_CONFIG *.field, and SHAPE *. Request selection, expansion, lookup, union, set operations, and compare require explicit names.

Workbook order: Summary → Index → Results → Postman folder sheets → response sheets → lookup sheets → union sheets → set-operation sheets → compare sheets. Empty response datasets are skipped. Large results may be split across multiple workbooks.

Current scope: multi-source joins are modeled internally but do not have a filter-language statement. Use LOOKUP_TABLE for request-per-row enrichment or the available union and set operations.

11

Troubleshooting

Common causes and the quickest correction.

ProblemFix
Request not foundCopy the exact, case-sensitive Postman request name from the request outline.
Date filter returns no rowsAdd the correct DATE_CONFIG format and timezone.
Wildcard filter or shape seems ignoredAn exact request/output rule replaces the wildcard default.
COLUMNS does not alter a lookupPut COLUMNS inside LOOKUP_TABLE.
FILTER does not alter union/set inputsThose operations read raw rows. Shape their generated output instead.
EXPAND * failsName the request explicitly.
Set operation returns zero rowsFull JSON rows must match exactly; use COMPARE when only one field should match.
Compare field is missingInspect the API response and use its flattened field path.
Report runs unexpected write requestsAdd REQUESTS; without it, every collection request executes.
