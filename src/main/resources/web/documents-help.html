OPERATIONAL PROCEDURE DOCUMENTS

Write procedures people can run.

OPDs are normal Markdown files. Keep each procedure focused, link the work around it, and let the preview show the document as readers will see it.

Open DocumentsMarkdown reference
01 · START A PROCEDURE

One purpose, clear ownership

Use a short title, state when the procedure applies, and give each action a result that can be checked.

# Release deployment

## When to use this
Deploying the approved release to production.

## Procedure
1. Confirm the release ticket is approved.
2. Run the deployment pipeline.
3. Verify the health endpoint returns 200.
02 · SAVE AND PREVIEW

Write without a save button

OPDs save shortly after you stop typing. Use Edit for a focused writing surface, Split to write beside the rendered result, or Preview to read the final document.

If another editor changes the same file, CEMS Studio stops the save and asks you to reconcile the two versions.

04 · CONNECT PROCEDURES

Link related OPDs

Write a note link with double brackets. Links use the OPD title or its Markdown filename. The destination OPD lists every procedure that links back to it.

Before beginning, complete [[Release checklist]].

For an alternate label, write
[[Release checklist|the release checklist]].

Links inside fenced code blocks are treated as examples and do not create backlinks.

05 · WORK WITH CATALOGS

Keep procedure knowledge and structured data together

Types

Define reusable classes or interfaces, their fields, relationships, inherited fields, and API methods.

Records

Create concrete data from a type. Table view is the default, and objects or arrays open as nested tables.

JSON

Use JSON view for bulk or precise edits. The draft must be valid JSON before it can be saved.
